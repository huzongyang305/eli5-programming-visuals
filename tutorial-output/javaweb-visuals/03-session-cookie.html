🍪 Session vs Cookie 对比

💡 生活类比：健身房会员

Cookie = 会员卡 - 你随身携带，每次出示证明身份（存在浏览器）

Session = 前台记录 - 健身房保存你的详细信息（存在服务器）

Session ID = 卡号 - Cookie里只存卡号，详细信息在服务器查

🖥️

Session

  • 存储在服务器
  • 更安全
  • 可存储大量数据
  • 会话关闭后失效
  • 占用服务器内存
🍪

Cookie

  • 存储在浏览器
  • 相对不安全
  • 容量有限(4KB)
  • 可设置过期时间
  • 不占用服务器资源
🖥️
浏览器
🍪 JSESSIONID=abc123
HTTP请求/响应
🖥️
服务器
Session: abc123
用户信息:
- 用户名: 张三
- 购物车: 3件商品

🔑 核心原理

1. 用户首次访问时，服务器创建Session并生成唯一ID

2. 服务器将Session ID通过Cookie发送给浏览器

3. 浏览器后续请求自动携带该Cookie

4. 服务器根据Session ID查找对应的Session数据

特性 Session Cookie
存储位置 服务器 浏览器
安全性 ⭐⭐⭐⭐⭐ 高 ⭐⭐ 低（可被篡改）
存储容量 几乎无限制 最大4KB
生命周期 会话结束即失效 可设置长期有效
服务器压力 占用内存 不占用
典型用途 登录状态、购物车 记住我、用户偏好
