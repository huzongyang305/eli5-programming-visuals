🏛️ 面向对象的四大支柱

🔒
封装 (Encapsulation)
把复杂的东西藏起来，只暴露简单的接口。就像汽车仪表盘，你不需要知道引擎怎么工作，只需要踩油门就行！
🌳
继承 (Inheritance)
子类可以继承父类的特性，并添加自己的特色。就像 SUV 继承了 Car 的基本功能，还增加了越野能力！
🎭
多态 (Polymorphism)
同样的方法调用，不同类型的对象会有不同的行为。就像"驾驶"这个方法，轿车和跑车的表现完全不同！
🎯
抽象 (Abstraction)
隐藏实现细节，只展示必要的功能。就像方向盘，你不需要知道转向系统如何工作，转动它就能转弯！

💡 封装的好处

  • 简化使用：用户只需关注简单接口，无需了解内部复杂性
  • 保护数据：防止外部直接修改内部状态，保证数据安全
  • 易于维护：内部实现可以改变，只要接口不变就不影响使用者
  • 降低耦合：各部分相对独立，修改一个部分不会影响其他部分

💡 继承的优势

  • 代码复用：子类自动获得父类的所有属性和方法
  • 层次清晰：从一般到特殊，结构一目了然
  • 易于扩展：新增类型只需创建新子类，不影响现有代码
  • 减少重复：共同特性在父类中定义一次即可

🎭 多态演示：同样的方法，不同的行为

选择车辆类型后点击"测试 drive() 方法"

💡 多态的核心思想

  • 统一接口：所有车辆都有 drive() 方法
  • 不同实现：每种车辆的 drive() 行为不同
  • 运行时决定：程序运行时才确定调用哪个版本
  • 易于扩展：新增车辆类型无需修改现有代码

💻 代码示例：继承与多态

C++ 版本 - Shape 基类

class Shape { // 基类 protected: string color; public: Shape(string c) : color(c) {} // 虚函数 - 支持多态 virtual double area() = 0; // 纯虚函数 virtual void draw() { cout << "Drawing a " << color << " shape" << endl; } }; class Circle : public Shape { // 派生类 private: double radius; public: Circle(string c, double r) : Shape(c), radius(r) {} double area() override { return 3.14159 * radius * radius; } void draw() override { cout << "Drawing a " << color << " circle with radius " << radius << endl; } }; class Square : public Shape { // 派生类 private: double side; public: Square(string c, double s) : Shape(c), side(s) {} double area() override { return side * side; } void draw() override { cout << "Drawing a " << color << " square with side " << side << endl; } }; // 多态使用示例 void renderShapes(vector<Shape*>& shapes) { for (auto* shape : shapes) { shape->draw(); // 根据实际类型调用不同版本 cout << "Area: " << shape->area() << endl; } }

Java 版本 - Abstract Shape 类

abstract class Shape { // 抽象基类 protected String color; public Shape(String color) { this.color = color; } // 抽象方法 - 必须由子类实现 public abstract double area(); // 具体方法 - 子类可以重写 public void draw() { System.out.println("Drawing a " + color + " shape"); } } class Circle extends Shape { // 子类 private double radius; public Circle(String color, double radius) { super(color); // 调用父类构造函数 this.radius = radius; } @Override public double area() { return Math.PI * radius * radius; } @Override public void draw() { System.out.println("Drawing a " + color + " circle with radius " + radius); } } class Square extends Shape { // 子类 private double side; public Square(String color, double side) { super(color); this.side = side; } @Override public double area() { return side * side; } @Override public void draw() { System.out.println("Drawing a " + color + " square with side " + side); } } // 多态使用示例 public static void renderShapes(List<Shape> shapes) { for (Shape shape : shapes) { shape.draw(); // 运行时多态 System.out.println("Area: " + shape.area()); } }

⚡ 编程范式对比：过程式 vs 面向对象

维度 过程式编程 (Procedural) 面向对象编程 (OOP)
核心思想 按步骤执行函数 对象之间交互协作
数据组织 数据和函数分离 数据和方法封装在一起
代码复用 函数调用 继承、组合、多态
扩展性 修改现有代码 添加新类，开闭原则
适合场景 简单脚本、算法实现 大型系统、复杂业务逻辑
学习曲线 较平缓，容易上手 较陡峭，概念较多
维护成本 小规模容易，大规模困难 初期投入大，长期易维护

🎯 如何选择？

  • 选择过程式：小型工具脚本、数学计算、性能敏感的底层代码
  • 选择面向对象：企业应用、游戏开发、GUI程序、需要长期维护的大型项目
  • 现代趋势：多数语言支持混合范式，根据实际情况灵活选择

🎯 核心要点总结

  • 类与对象：类是蓝图，对象是根据蓝图创建的实例
  • 封装：隐藏内部复杂性，提供简单接口
  • 继承：子类复用父类特性，形成层次结构
  • 多态：同一接口，不同实现，运行时决定
  • 抽象：关注做什么，而非怎么做
  • OOP优势：代码复用、易于维护、贴近现实、团队协作友好
  • 适用场景：大型项目、复杂业务、需要长期维护的系统
