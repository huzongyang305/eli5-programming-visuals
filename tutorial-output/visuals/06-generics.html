📖 ELI5: 泛型是什么？

万能食谱书：一份配方，多种食材

💡 生活类比：万能食谱书

想象你有一本万能食谱书：

  • 模板/泛型 = 带有占位符食材的食谱（比如""代表任意食材）
  • 实例化 = 填入真实食材（整数、字符串、自定义类型）
  • 类型安全 = 厨房防止混合不兼容的食材（不能把数字和文字混在一起煮）

核心思想：写一次代码，适用于多种数据类型，编译器帮你检查类型错误！

🍳 通用容器食谱

📖 发生了什么？

当你在编译时指定具体类型，编译器会生成该类型的专属版本！

⚙️ 编译时 vs 运行时类型检查

// C++ 模板：编译时生成具体代码
template<typename T>
class Box {
    T value;
public:
    void set(T v) { value = v; }
    T get() { return value; }
};

// 编译时生成两个独立版本
Box<int> intBox;      // → 生成 Box_int 类
Box<string> strBox;   // → 生成 Box_string 类

intBox.set("hello");  // ❌ 编译错误！类型不匹配
❌ 编译错误： cannot convert 'const char*' to 'int' in assignment
✅ 编译成功： 类型检查通过，生成高效机器码

⚠️ Java 类型擦除的限制

  • 运行时无法获取泛型类型信息
  • 不能创建泛型数组：List<T>[] 非法
  • 不能用 instanceof 检查泛型类型
  • 静态方法不能使用类的泛型参数

🎨 C++ 模板特化：定制特殊食谱

📋 通用模板

template<typename T>
class Box {
    T value;
public:
    void print() {
        cout << value;
    }
};

适用于所有类型

🎯 string 特化版本

template<>
class Box<string> {
    string value;
public:
    void print() {
        cout << "[str]" 
             << value;
    }
};

为 string 定制行为

📖 模板特化说明

当某个类型需要特殊处理时，可以提供专门的实现。编译器会优先使用特化版本！

🎪 可变参数模板：接受任意数量的食材

就像一道可以放任意数量配料的沙拉！

    (cout << ... << args);

// 可以传入任意数量和类型的参数
printAll(1, "hello", 3.14, true);

⚔️ C++ 模板 vs Java 泛型对比

特性 C++ 模板 Java 泛型
实现机制 编译时代码生成 类型擦除（Type Erasure）
性能 ⭐ 零开销，内联优化 🐢 有装箱/拆箱开销
特化支持 ✅ 完全支持模板特化 ❌ 不支持
类型约束 SFINAE / Concepts (C++20) 通配符
编译错误信息 😱 可能非常冗长复杂 😊 相对清晰易懂
代码膨胀 ⚠️ 每种类型生成独立代码 ✅ 只有一份字节码
运行时类型信息 ✅ 保留完整类型信息 ❌ 泛型类型被擦除
元编程能力 🚀 强大的编译期计算 🔧 有限的反射能力

💡 如何选择？

  • C++ 模板：追求极致性能、需要特化、编译期元编程
  • Java 泛型：简化开发、向后兼容、运行时灵活性

🎯 泛型的实际应用场景

📦 容器类

List<T>, Map<K,V>

存储任意类型的数据集合，保持类型安全

List<String> names = 
    new ArrayList<>();
names.add("Alice");
String name = names.get(0);

🔧 算法模板

sort(), find(), filter()

对任何可比较类型执行相同算法

template<typename T>
void sort(vector<T>& v) {
    // 排序逻辑
}

🏭 工厂模式

Generic Factory

根据类型动态创建对象

template<typename T>
T* create() {
    return new T();
}

🏗️ Builder 模式

Fluent API with Generics

链式调用保持类型信息

class Builder<T> {
    Builder<T> setName(String n);
    Builder<T> setAge(int a);
    T build();
};

⚠️ 泛型的局限性

🚫 Java 不能使用基本类型

List<int> ❌ 非法！必须用包装类 List<Integer>

原因：类型擦除后变成 List，而基本类型不是对象

🚫 类型擦除的限制

  • 运行时无法知道 List<String> 原本是 String 类型
  • 不能创建泛型数组：new T[10] 编译错误
  • 不能用 instanceof T 进行类型检查

🚫 C++ 模板编译错误难以阅读

// 错误信息可能长达几百行！
error: no match for 'operator+' in 
'std::basic_string + int'
... (200 more lines of template instantiation trace) ...

🚫 代码膨胀问题

C++ 中每种类型组合都会生成独立代码，可能导致二进制文件变大

解决方案：使用指针或引用减少实例化，C++17 的 std::variant

📝 总结

🎓 关键要点

  • 泛型 = 万能食谱：写一次，适配多种类型
  • 类型安全：编译器在编译时检查类型错误，避免运行时崩溃
  • C++ vs Java：编译时生成 vs 运行时擦除，各有优劣
  • 实际应用：容器、算法、设计模式都离不开泛型
  • 注意局限：了解每种语言的泛型限制，选择合适的方案
