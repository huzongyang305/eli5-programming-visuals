# ELI5 编程基础可视化图解系列

> **Explain Like I'm 5** - 用生活类比和互动动画，让复杂编程概念变得简单易懂

## 📚 概览

本系列包含 **8个交互式HTML可视化页面**，每个页面都通过生活类比、动画演示和互动控件来解释一个核心编程概念。所有页面都是**完全自包含的单个HTML文件**，无需任何外部依赖，可直接在浏览器中打开。

## 🎯 设计理念

- **生活化类比**：将抽象概念映射到日常生活场景（火车车厢、俄罗斯套娃、汽车工厂等）
- **视觉化呈现**：使用CSS动画和JavaScript交互展示数据结构和算法的动态过程
- **渐进式学习**：从直观理解 → 代码示例 → 性能分析 → 最佳实践
- **双语言对照**：同时提供 C++ 和 Java 代码示例，对比两种语言的实现差异
- **零门槛访问**：单文件设计，离线可用，无网络依赖

## 📖 可视化清单

### 1. [链表是如何工作的？](01-linked-list.html) 🔗
**生活类比**：火车车厢系统

每节车厢包含货物（数据）和下一节车厢的位置（指针）。通过动画展示节点的插入、删除和遍历操作。

**核心特性**：
- 动态节点添加/删除动画
- 与数组的性能对比表
- C++ `std::list` vs Java `LinkedList` 代码示例
- 内存分配可视化

---

### 2. [递归是如何工作的？](02-recursion.html) 🪆
**生活类比**：俄罗斯套娃

打开一个娃娃发现里面还有更小的娃娃，直到最小的娃娃（基准条件）。展示函数调用栈的堆叠和展开过程。

**核心特性**：
- 阶乘计算的逐步动画
- 调用栈深度实时显示
- 记忆化优化前后对比（O(2ⁿ) → O(n)）
- 常见错误：缺失基准条件导致无限递归

---

### 3. [面向对象编程是什么？](03-oop.html) 🚗
**生活类比**：汽车工厂

类是设计蓝图，对象是实际生产的汽车。通过工厂生产线展示四大支柱：封装、继承、多态、抽象。

**核心特性**：
- 点击生产不同车型（Sedan/SUV/跑车）
- 引擎盖开关展示封装（隐藏内部复杂性）
- 继承树可视化（Car → SUV → OffRoadVehicle）
- 多态行为测试（同一 `drive()` 方法的不同表现）

---

### 4. [内存是如何管理的？](04-memory-management.html) 📚
**生活类比**：图书馆书架系统

- **栈**：书桌旁的快速存取架（自动清理，LIFO）
- **堆**：主书库（手动预约/归还，灵活大小）
- **垃圾回收器**：定期清理未使用书籍的管理员

**核心特性**：
- 栈 push/pop 动画
- 堆内存分配/释放可视化
- 智能指针引用计数演示
- 内存泄漏检测与GC周期动画

---

### 5. [异常处理是如何工作的？](05-exception-handling.html) 🚒
**生活类比**：应急响应团队

- **try块**：建筑物内的正常运营
- **throw**：触发火警报警
- **catch**：专业消防队响应
- **finally**：无论结果如何都运行的清理小组

**核心特性**：
- 异常沿调用栈向上传播动画
- 不同异常类型的颜色编码（火灾/文件丢失/网络错误）
- 异常链可视化（因果关系）
- Checked vs Unchecked 异常对比

---

### 6. [泛型是什么？](06-generics.html) 📖
**生活类比**：万能食谱书

模板/泛型是带占位符 `<T>` 的食谱，实例化时填入实际类型（int、string等）。类型安全如同厨房防止混合不兼容食材。

**核心特性**：
- 类型替换动画（Box<int> → Box<string>）
- C++ 模板特化演示（为特殊类型定制版本）
- Java 类型擦除逐步展示（编译后移除类型信息）
- 可变参数模板（接受任意数量参数）

---

### 7. [哈希表是如何工作的？](07-hash-table.html) 🗂️
**生活类比**：图书馆卡片目录

书名（键）通过目录编号系统（哈希函数）映射到书架编号（桶索引）。两本书映射到同一书架时产生冲突，通过链式法解决。

**核心特性**：
- 哈希函数计算可视化（字符串 → 数字 → 桶索引）
- 冲突处理策略对比（链式法 vs 开放寻址）
- 负载因子调节滑块（50%-90%）
- 重新哈希动画（扩容时重新分布所有元素）

---

### 8. [SOLID设计原则是什么？](08-solid-principles.html) 👨‍🍳
**生活类比**：餐厅厨房组织

- **SRP**：每位厨师专精一项技能（副厨、糕点师、烧烤师）
- **OCP**：菜单可添加新菜品而无需改变厨房布局
- **LSP**：任何替代食材都能在食谱中正常工作
- **ISP**：厨师只需自己工位的工具，而非整个厨房
- **DIP**：厨房向供应商下单，而非特定农场

**核心特性**：
- 违反 vs 遵循原则的切换对比
- 依赖关系图可视化（紧耦合 → 松耦合）
- 重构动画展示改进过程
- 互动测验模式（识别违反的原则）

## 🚀 使用方法

### 方式一：直接打开
双击任意 `.html` 文件即可在默认浏览器中打开。推荐按顺序学习：

```
index.html（总索引页）
  ↓
01-linked-list.html
  ↓
02-recursion.html
  ↓
...（依此类推）
```

### 方式二：本地服务器
为避免某些浏览器的跨域限制，可使用 Python 启动本地服务器：

```bash
cd tutorial-output/visuals
python -m http.server 8080
```

然后在浏览器中访问：`http://localhost:8080/index.html`

### 方式三：嵌入教程
这些可视化页面可作为教程章节的补充材料，通过 iframe 或链接嵌入 Markdown 文档：

```markdown
[查看交互式可视化](visuals/01-linked-list.html)
```

## 🎨 技术特点

### 视觉设计
- **配色方案**：紫色渐变主题（#667eea → #764ba2），保持一致性

### 代码示例
- **语法高亮**：关键字、类型、注释、函数分别着色
- **双语言对照**：左侧 C++，右侧 Java，方便对比学习
- **最佳实践标注**：绿色标记推荐做法，红色标记常见错误
